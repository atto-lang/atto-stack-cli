# Authored .ores leaves and generated .ores adapters

This is a **source-level** first implementation of Oreslang Stack's CLI. Actual Oreslang compiler integration, typed schema generation and Lambda runtime packaging are separate admission gates.

## API tree

\`\`\`text
src/routes/users/[id]/
  handlers.ores  # authored domain logic
  route.ores     # authored HTTP method/path and handler forwarding authority
  rpc.ores       # 100% generated sibling: route forwarding adapter
  lambda.ores    # 100% generated sibling: RPC forwarding adapter
\`\`\`

A \`route.ores\` may declare multiple \`// @ores-route <METHOD> <PATH> <SYMBOL>\` directives, each pointing to a \`pub fnc SYMBOL(String request) -> String\` forwarder and a sibling same-signature \`handlers.ores\` implementation. Path is canonicalized from the folder name, with \`[param]\` matching \`{param}\`; route shapes with different parameter names at the same position cannot coexist.

The generated RPC forwarding function is \`rpc_<symbol>\`, while the generated Lambda forwarding function is \`invoke_<symbol>\`. They currently carry an **opaque String** transport envelope and do **not** pretend to implement typed RPC schema validation or AWS/GCP transport plumbing. Transport/auth/runtime adapters remain explicit external tasks.

## Web tree

\`\`\`text
src/pages/users/[id]/
  page.ores      # authored page handler, \`// @ores-page <PATH> <SYMBOL>\`
  lambda.ores    # generated page-forwarding stub, no RPC identity
\`\`\`

For web or admin-web, do not declare \`@ores-route\` or generate \`rpc.ores\`. The real SSR library is [oreslang-ssr](https://github.com/ores-truffle-oreslang/oreslang-ssr); this adapter deliberately does not implement an HTML engine in Rust.

## Fail-closed behavior

- The manifest \`oreslang-stack.toml\` explicitly declares role \`api\`, \`admin-api\`, \`web\` or \`admin-web\`; role is never inferred from a repository name.
- \`generate all --check\` does no writes; it rejects missing, changed and orphan generated outputs. Generated \`.ores\` sources carry \`// @generated by oreslang-stack-cli; DO NOT EDIT.\`.
- Generated \`rpc.ores\` and \`lambda.ores\` are only synchronized when their direct source authorities pass discovery checks. Filesystem symlinks and path ambiguities fail closed.
- \`check\` invokes the actual configured \`oreslang check\` compiler command on discovered Oreslang files. The CLI only asserts compiler approval if that invocation succeeded. The compiler may not yet accept the scaffold ABI or module import paths; CI only checks the host CLI/source-level contract, not language runtime proof.
- Native \`oreslang-http-routing\`, \`oreslang-rpc\`, and \`oreslang-ssr\` are separate **Oreslang-written** libraries. The eventual artifact generator must link them under exact, tested revisions; this initial transport-neutral boundary makes no claim that typed adapters are complete.
